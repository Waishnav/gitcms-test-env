# Docs components browser QA

Run against the feature worktree and exact local origin using `.agents/skills/gitcms-qa/SKILL.md` in gitcms-apps. Bootstrap separate `owner` and `editor` sessions with `pnpm qa:browser -- --app-url <origin> --persona <owner|editor>`. The editor has no publish permission. Use only `Waishnav/gitcms-test-env`; use disposable content tasks/drafts, never edit baseline `main` during browser QA. Record app commit, fixture baseline SHA, origin, persona, screenshots and issue repros. Repeat each applicable scenario for both personas and both sites; owner may publish, editor must request review instead. Compare draft Git refs before and after each action: `git diff --no-ext-diff --unified=3 <before> <after> -- <path>` and `git diff --name-status <before> <after>`. If no commit is created for a no-op, compare the saved draft file byte-for-byte with `git show <before>:<path>`; no commit is an acceptable zero diff. Reset via a fresh disposable task between cases, preserving evidence. Paths below are relative to repository root.

Fumadocs files are `sites/fumadocs/content/docs/gitcms-qa/*.mdx`; Starlight files are `sites/starlight/src/content/docs/gitcms-qa/*.mdx`. Starlight is a standalone site scaffolded from the official template.

**Availability:** `#496` means parsing, preservation and fallback are testable on that stack before PR 4; `PR 4` means component editing/regions/props behavior needs PR 4. These are expectations to verify, not claims that unmerged work already passes.

1. **No-op saves — #496.** Open each curated page and at least one existing real docs page per site, save without editing. Expected: content remains unchanged, with no spurious formatting. Git: zero changed paths and byte-identical file, including frontmatter, whitespace, imports and line endings.
2. **Paragraph — #496.** Change one ordinary paragraph on a real page, save. Expected: only that text changes. Git: one file; diff contains only that paragraph's intended text, no surrounding source changes.
3. **Callout — PR 4.** In Fumadocs `callouts.mdx`, edit Information title in place, change type via props, add bold and a link to its body; save. Expected: edits appear in the card and persist on reopen. Git: only that Callout's title, type and edited body change; all other Callouts and whitespace remain byte-identical.
4. **Card — PR 4.** In `cards-steps.mdx`, change the description-backed Card title and description in place, then href and external in props; save. Repeat with the child-backed and both-source cards. Expected: changes persist and no content disappears. Git: only the chosen Card's intended attributes/children change; inspect both-source card carefully for loss or duplication.
5. **Tabs — PR 4.** In `tabs-accordions.mdx`, add a tab, rename its label, remove the Beta tab, save and reopen. Expected: labels and tab content agree; nested Callout survives. Git: only `<Tabs items={...}>` and the intended Tab additions/removal/label change; items array matches child values in order; nested Callout bytes unchanged.
6. **Steps — PR 4.** Edit first step paragraph and add a step in Fumadocs `cards-steps.mdx`. Expected: ordered steps persist. Git: only that paragraph and one new `<Step>` change; neighboring Cards and second step unchanged.
7. **Accordion — PR 4.** Edit first title and rich body in `tabs-accordions.mdx`. Expected: both persist. Git: only first Accordion title/body change; Tabs and second Accordion unchanged.
8. **Files — PR 4.** Rename `src` and add a File within it in `files-types.mdx`. Expected: hierarchy persists. Git: only the Folder name and new File change; nested folder and TypeTable unchanged.
9. **Starlight — PR 4.** In `asides-tabs.mdx`, edit Aside title/type/body, rename/add/remove a TabItem and edit both directives. In `cards-steps.mdx`, edit Card title/body/icon and LinkCard href, edit and add a Steps list item. In `file-tree.mdx`, rename and add a nested list item. Expected: regions and list hierarchy persist, directives retain their syntax. Git: only selected attributes, directive label/body, or list items change respectively; imports, unrelated components, list indentation and surrounding text remain unchanged. Check `syncKey` and TabItem labels/icons remain valid.
10. **Opaque syntax — #496; component read-only UI requires PR 4.** Open Fumadocs `preservation.mdx`; attempt edits to `<MyWidget>` and the Card's `href={target}`, then edit a separate normal paragraph and save. Expected: unknown component and non-literal expression are read-only and retained. Git: only the ordinary paragraph changes; import/export, expression and unknown component remain byte-identical.
11. **Inline JSX — #496; locked UI requires PR 4.** Attempt to edit the inline JSX paragraph in `preservation.mdx` and the Badge paragraph in Starlight `file-tree.mdx`; edit a different paragraph and save. Expected: inline JSX paragraphs are locked, no partial destructive edit. Git: only the unrelated paragraph differs; entire inline paragraph is byte-identical.
12. **Invalid MDX — #496.** Copy `sites/fumadocs/gitcms-qa/invalid.mdx` to `sites/fumadocs/content/docs/gitcms-qa/invalid.mdx` on a disposable fixture branch/task (never baseline main); open it. Expected: text fallback and error banner. Close the tag in text, save and reopen: visual editor returns. Then attempt a visual edit that cannot be serialized safely. Expected: refusal with a message, no silent corruption. Git: initial invalid copy matches source byte-for-byte; fix diff adds only `</Callout>`; refused edit produces zero diff. Remove the disposable copy after the run. The fixture copy is outside the site content glob because an unclosed component fails MDX compilation.
13. **Undo/redo — PR 4.** Edit title, body and prop on a Callout, undo each, redo each, save. Expected: each operation reverses/reapplies in order with focus intact. Git: final diff equals intended three edits only; after undoing all and saving, zero diff.
14. **Keyboard boundaries — PR 4.** Place caret at beginning/end of component regions and press Enter and Backspace, including empty Steps and FileTree list items. Expected: normal paragraph/list behavior without merging, deleting or escaping neighboring component structure unexpectedly. Git: only intended paragraph/list item changes; compare tags, nesting and neighbors byte-for-byte.
15. **No preset — #496 (repeat on PR 4).** Open an existing configured site without components presets and save a representative MDX/Markdown entry, then edit a paragraph. Expected: prior editor behavior; no catalog-induced conversion. Git: no-op zero diff; paragraph edit changes only that paragraph and never adds component config.
16. **Review — PR 4.** As editor create a content task, edit a component and request review; inspect as owner, then approve/publish only in the disposable task. Expected: editor cannot publish; review displays intended component changes and owner can publish. Git: draft diff contains only intended component edits; published commit contains the same content changes, with no unrelated paths. Verify editor's denied publish attempt creates no publication commit.
