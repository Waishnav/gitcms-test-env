# GitCMS configuration

GitCMS (https://gitcms.dev) reads this folder to edit the site's content. Prefer changing it in the GitCMS app; when you edit these files directly:

- A collection exists because `sites/<site_key>/collections/<name>.jsonc` exists, and site data because `sites/<site_key>/singletons/<name>.jsonc` exists. To add, rename, or remove one, add, rename, or delete its file.
- Names are lowercase letters, numbers, `-`, and `_`. The file name is the name; don't put a `name` inside the file.
- `collections` and `singletons` in `config.jsonc` only set the order in the sidebar. Items they don't list come after, alphabetically.
- `components.presets` in a site's `config.jsonc` lists the built-in component catalogs its entries use: `fumadocs`, `starlight`, and `github-alerts`. A site renders one docs framework, so list at most one of `fumadocs` and `starlight` (both together is reported as a problem, and neither is applied: their components stay raw). Add `github-alerts` for sites that render GitHub's `> [!NOTE]` alerts (VitePress, Nextra, or a plugin such as `remark-github-blockquote-alert` or `rehype-github-alerts`); next to a framework, add it only when a plugin makes that framework render them. Without it, alerts are edited as the plain quotes the site publishes.
- A site's own MDX component is defined by `sites/<site_key>/components/<Name>.jsonc`, named exactly like its tag (`MyWidget.jsonc` for `<MyWidget>`), starting with a capital letter (a lowercase tag is an HTML element in MDX). It holds a component spec without `name`: `dialect` (`mdx-jsx`), `props` (fields, as in collections), and optionally `attributeRegions`, `childrenRegion`, `childComponent`, `children` and `import`. A component that is only its props (`<YouTube id="…" />`, with `"children": { "kind": "none" }`) needs no regions: editors get a card with its fields. It replaces a preset component of the same name. A definition that doesn't validate leaves that component uneditable, even when a preset has one by that name; `npx create-gitcms check` reports it. Definitions are site config, like collections and site data: they take effect once they're on the site's configured branch, and adding one inside a content task's draft doesn't change that task's editor.
- Don't change `version` by hand. To upgrade, run `npx create-gitcms migrate --write`.
- After editing, run `npx create-gitcms check` and fix anything it reports.
